# データ追加ガイド

## 1. 業種ファイルを追加する

`data/industries/`の既存ファイルを複製し、`id`、`name`、`profiles`を変更します。`data/manifest.json`の`industries`に、そのファイルの相対パスを登録します。静的ホスティングではディレクトリ内のJSONを自動列挙できないため、**ファイルを置くだけでなくmanifest登録も必要です**。

```json
{"id":"sample-industry","name":"架空業種","path":"data/industries/sample-industry.json"}
```

既存業種へ職種を増やす場合は、その業種ファイルの`profiles`へ追加するだけです。

## 2. 職種ごとの内容を作る

各職種には次の情報を用意します。

| 項目 | 内容 |
| --- | --- |
| id / role / department / company | 一意な職種ID、表示名、部門、架空の組織名の語幹 |
| theme / product / productType | 業務テーマ、架空製品名、具体的な用途 |
| objective / issue | 達成する状態と、業務改善が必要になった背景 |
| inputs / outputs | 入力として必要な情報と、後続へ渡す成果物 |
| skills / must / preferred / metric | スキル一覧、必須・歓迎条件、指標の正確な意味 |
| phases | title、action、rule、evidenceを持つ業務工程の配列 |
| cases | title、problem、decision、followupを持つ具体事例の配列 |
| scenes | id、name、templatesを持つ利用シーンの配列 |

`rule`には「どの条件で処理を止めるのか」を具体的に記載してください。`evidence`には「何を残せば第三者が判断を追えるのか」を記載します。「適切に処理する」だけでは本文の質は上がりません。

初期データは1職種につき6工程と4事例です。事例数を減らしても動作しますが、詳細モードの文章量が減ります。必要な情報を増やす方向で拡張し、同じ段落の繰り返しで文字数を増やさないでください。

## 3. 文書テンプレートを追加する

`data/templates/longform.json`の`templates`に一意なIDで追加し、利用シーンの`templates`配列から参照します。既存のテンプレート構造に従えば、JavaScriptへ業種や文書ごとのif文を追加する必要はありません。

- `facts`：必ず本文へ収録する根拠段落と、そこから回答できる質問。`id`、`title`、`text`、`question`、`answer`、`kind`を指定します。
- `sections`：章ID、見出し、標準本文`paragraphs`、長文で追加する`extended`、詳細で追加する`deep`。
- `phaseTitle` / `phaseText`：各工程の文章化。
- `caseTitle` / `caseText`：各事例の文章化。

差し込みは `{{role}}` の形式です。任意のJavaScriptや式を実行する機能はありません。未定義の変数があればエラーになります。追加した職種の文字列項目は差し込み値として利用できます。数値の新しい相互関係を導入する場合は、`js/content-engine.js`で一度だけ計算し、全箇所で同じ値を使用します。

## 4. RAGの正解を確認する

質問には対象文書IDが自動で付きます。正解は必ず対応する`facts.text`から得られる内容にしてください。期待回答が本文のどの箇所からも説明できない質問を追加しないでください。文書にない質問は`answerable=false`として別に扱います。

評価ファイルの原文根拠は、生成した段落そのものを使用します。本文から切り出して正解を作るため、同じ差し込み値を別々に乱数生成しないでください。

## 5. 個人情報や機密らしい値を入れない

実際の履歴書や求人票、顧客資料、社内手順を転記しないでください。氏名・住所・電話・口座・実在メール・秘密鍵・パスワード・トークンは不要です。組織名は架空の語幹だけを使い、生成時に付く`【架空】`表記を削除しないでください。

採用関連の確認項目は職務に関係する行動と経験に限定します。実際の個人の属性や機微情報を模した項目を追加しないでください。経理データは数値や状態のテストであり、法令や税務判断を再現するものではありません。

## 6. テストして公開する

```
node tests/content.test.mjs
```

すべての職種×文書×長さで、未置換の差し込み、根拠の存在、件数整合性、再現性を確認します。新しい文書で必要な条件が増えた場合はテストも追加してください。文字数を変えたらUIの目安表示も見直します。ロジックやデータを変更した場合はバージョンと読み込みURLの版を更新し、Pagesへの反映を確認してください。
