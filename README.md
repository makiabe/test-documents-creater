# Test Documents Creator v1.1

GitHub Pagesで動作する、長文の架空業務ドキュメント生成アプリです。実行時に生成AIを呼び出さず、手書きの架空シナリオ・文章テンプレート・整合した数値から本文を組み立てます。

## 収録内容

初期データは7業種、8職種、24利用シーン、6種類の文書テンプレートです。

- 業種：IT・情報サービス、製造、物流、小売、人材・人事、経理・事務、教育・研修。
- 文書：職務経歴書、求人票、製品マニュアル、業務マニュアル、業務報告書、FAQ。
- 内容：背景、担当範囲、具体的な手順、判断条件、例外対応、根拠の残し方、改善事例。

標準は約2,500〜3,000字、長文は約4,000〜4,600字、詳細は約5,700〜6,400字。初期データの目安です。実際の文字数を一覧に表示します。件数は10・30・50ファイルで、選択した形式に振り分けます（形式数を掛けた件数ではありません）。

## 出力

| 形式 | 収録方法 |
| --- | --- |
| DOCX | 目次、章見出し、本文、章ID、ページ番号を持つ文書 |
| XLSX | 文書情報・段落別の全文・章索引の3シート。長い段落は分割行へ収録 |
| PPTX | 本文を省略せず複数スライドに分割。長文ではスライド枚数が多くなります |
| PDF | 日本語フォントを埋め込んだテキストPDF。画像化しません |

プレビューは共通データの全文をHTMLで表示するものです。Office/PDF自体のレンダリングではありません。本文の文字数はヘッダー・章ID等を含む共通テキストの文字数で、ページ数を固定するものではありません。

## RAG評価

ZIPには任意で次のファイルを追加できます。

```
documents/                     # RAGの検索対象はここだけ
_evaluation/questions.jsonl    # 質問・期待回答例・原文根拠・章ID
_evaluation/README.txt
_metadata/manifest.json        # シード、文書ID、文字数、元ファイルなど
```

評価ファイルを検索対象へ入れないでください。正解漏洩の原因になります。質問は事実抽出、条件付き判断、文書に回答がない質問を含みます。生成時に正解の根拠が本文に存在することをテストします。期待回答は例であり、自動採点機能ではありません。

**各文書は独立した架空ケースです。** 文書IDで対象を特定してください。同名の製品でも別ケースには異なる条件があります。v1.1は、複数文書をまたぐ関連セットや旧版・新版の正解付き比較までは実装していません。テンプレート由来の共通文章があり、50件すべてが完全に異なる原稿になるわけではありません。

## 再現性

業種・職種・文書選択・形式選択・シード・長さ・ジェネレーター/データの版が同じなら、同じ本文と文書IDを再生成できます。ZIPやOfficeファイルにはライブラリ由来の日時が入り得るため、バイナリ全体の同一性は保証しません。`contentFingerprint`は本文比較用の非暗号学的指紋です。

## データ追加

アプリの分岐を増やさずJSONを追加します。詳細は [データ追加ガイド](docs/ADDING_DATA.md) を参照してください。

```
data/manifest.json               # 業種ファイル一覧
 data/industries/it.json          # 職種、利用シーン、背景、手順、具体事例
 data/industries/manufacturing.json
 data/industries/logistics.json
 data/industries/retail.json
 data/industries/hr.json
 data/industries/accounting.json
 data/industries/education.json
 data/templates/longform.json     # 文書種類ごとの構成・本文・正解根拠
```

`data/catalog.json`は旧v1.0の資料として残しています。v1.1のUIは`data/manifest.json`を読み込みます。

## 安全な架空データ

実在データの匿名化ではなく、初めから架空の内容を作ります。氏名の代わりに`TEST-PERSON-...`、組織には`【架空】`とケース番号を付けます。生年月日、実在住所、連絡先、口座番号、認証情報は生成しません。短い架空名称が実在名称と偶然一致しないことまでは保証できないため、常に架空表記を残してください。

求人条件・製品仕様・締切・承認条件はすべてテスト上の仮定です。実際の求人や業務手順、法令・契約・税務の判断には使用しないでください。

## 通信と文字コード

生成する本文をサーバーへ送信する処理はありません。画面から実在文書をアップロードする機能もありません。初期データはGitHub Pagesから、出力ライブラリはCDNから、PDF用フォントはGoogle Fontsの公開リポジトリから取得します。完全な無通信/初回オフライン動作を保証する構成ではありません。取得に失敗した場合はエラーを表示し、画像PDFや`[JP]`への置換でごまかしません。

ソース、データJSON、評価JSONL/TXTはUTF-8です。Office/PDFの内部形式は各仕様に従います。CSV/TXTのShift_JIS出力は未実装です。

## ローカル確認

```
python -m http.server 8000
# http://localhost:8000 を開く（file:// では起動しないでください）
node tests/content.test.mjs
```

ブラウザ/出力の統合テストは `npm install`、`npx playwright install chromium` の後、`npm run test:browser`。PDFの文字抽出チェックには `pdftotext`（Poppler）が必要です。統合テストはCDNおよびフォント取得のために通信します。

## 第三者ライブラリ

JSZip 3.10.1（MIT/GPL dual）、PptxGenJS 4.0.0（MIT）、jsPDF 4.2.1（MIT）、M PLUS 1p（SIL Open Font License）を使用します。DOCX/XLSXはJSZipとOffice Open XMLのテキスト部品から出力します。フォント取得元は `js/exporters.js` にコミット固定のURLを記載しています。
